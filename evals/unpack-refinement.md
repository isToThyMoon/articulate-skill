# Unpack 证据边界优化与复测

## 修正

- 在共同方法中明确：改写、示例与可复制要求必须保留原有证据边界；不能靠前文免责声明把假设包装成现状。这条规则同步到三个 skill。
- unpack 区分“结论成立所需条件”与“作者实际采用的假设”，避免揣测作者。
- 默认只交付一份可迁移表达，不主动再附重复评审改写；五层理解服务学习，不把拆解变成固定找错清单。

## 测试过程

复用两个 GPT-5.6 Sol 会话，不是新上下文盲测。均要求不联网，以用户给定原文为材料；主 agent 审查实际输出。UI 输入与原 smoke test 相同；写作输入是已含条件判断的限知视角/潜台词评语，用户希望理解概念而非改稿。

| 输出 | 观察 |
|---|---|
| [UI 首次复测](unpack-retest-ui.md) | 可复制要求较谨慎，但额外评审改写仍以未经验证的页面现状开头，未通过目标检查 |
| [UI 反馈后复测](unpack-retest-ui-final.md) | 明确没有页面材料，把意图解释标为推断；仅一份表达且不预设设置过多，目标缺陷未再出现 |
| [写作首次测试](unpack-retest-writing.md) | 五层解释实质充分，但示例添加“三次动作”“前文缺失”而未明确标为假设，未通过目标检查 |
| [写作反馈后复测](unpack-retest-writing-final.md) | 开头限定只有评语无正文；保留原文“若”的条件；新情境明确教学假设，没有将新造次数或缺失前文当事实 |

两份最终回答均解释概念、易混淆项、关系、使用阶段、评价与迁移，而不是只列术语。写作测试保留原评语合理之处，未强行判错；两者均未联网或伪造出处。

## 结论与局限

针对本次“假设在改写中升级成事实”的目标，反馈后样本有明确改善。但首次复测仍暴露问题，不能宣称改规则即可保证一次成功。UI 最终回答还把若干策略适用条件表述成“至少需要”，应谨慎区分常见考虑因素与逻辑必要条件；整体篇幅也偏长。未核验全部领域事实，未重测 orient/clarify 的完整行为，也未验证真实用户学习效果。

机械检查：三个 skill 格式通过；共享副本一致；同步脚本语法通过；仓库与本机安装内容一致；diff 空白检查通过。没有新增学习记录或强制课程。
