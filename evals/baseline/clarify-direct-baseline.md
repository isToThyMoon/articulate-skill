**任务：把首页视觉升级到更高级的质感，不改业务功能**

**目标**
让首页第一眼看起来克制、精致、可信，像成熟品牌的官网，而不是模板站。现有的信息结构、文案含义、链接、交互和数据逻辑都保持不变。

**开始前先做（不要跳过）**
1. 读首页的代码和样式，找出现在用的技术栈和样式方案（比如 Tailwind、CSS Modules、组件库），沿用它们，不要引入新的 UI 框架。
2. 列出首页有哪些区块（导航、首屏、特性、案例/数据、CTA、页脚等）。
3. 找出让页面显得“廉价”的具体问题，写成一张简短清单，每条都指明位置。常见问题包括：颜色太多或饱和度太高、字号层级混乱、间距不统一、阴影和圆角滥用、渐变和图标堆砌、首屏信息过载、对齐不齐。

**改造方向**
- **色彩**：收敛到 1 个主色、1 组中性灰阶，最多再加 1 个强调色。降低饱和度，大面积用留白和中性色，主色只用在关键 CTA 和少量重点上。去掉装饰性的彩色渐变。
- **字体与排版**：建立清晰的字号阶梯（比如 12/14/16/20/28/40/56，按项目实际情况调整）。首屏标题要大、字重适中、行高紧凑、字间距略收；正文行高 1.5–1.7，每行控制在 60–75 个字符。全页最多用 2 个字重档位做区分。
- **间距与布局**：统一使用 4 或 8 的倍数作为间距。区块之间的上下留白明显加大（桌面端建议 96–160px）。内容最大宽度统一，网格对齐严格。每个区块只讲一件事。
- **首屏**：只保留一句核心价值主张、一句补充说明，主 CTA 和次 CTA 各一个，再配一个高质量的视觉元素（产品截图、简洁插画或留白）。删掉首屏里多余的徽章、标签和装饰图形。
- **细节质感**：圆角统一为 1–2 个值；阴影要轻、柔、少，优先用 1px 的细边框或背景色差来分层；图标风格和线宽统一；图片统一比例和处理方式。
- **动效**：只加克制的微交互，包括 hover 过渡（150–250ms，ease-out）、区块进入时轻微的淡入上移。不要视差、弹跳或自动轮播。遵守 `prefers-reduced-motion`。
- **暗色模式**：如果项目已经支持，就同步调整；如果不支持，不要新增。

**约束**
- 不改文案含义（可以精简冗余措辞，但要在改动说明里列出来），不删功能，不改路由和埋点。
- 颜色、字号、间距、圆角、阴影全部抽成 design token 或 CSS 变量，不要到处硬编码。
- 必须同时适配移动端（375px）、平板（768px）和桌面（1440px），不能出现横向滚动。
- 可访问性：文字对比度达到 WCAG AA，焦点状态可见，语义化标签不能退化。
- 性能不能变差：不引入大体积依赖；图片使用合适的尺寸和格式，并懒加载。

**交付物**
1. 最开始列出的问题清单，以及每条问题对应的改法。
2. 代码改动，尽量集中在首页和 token 文件里。
3. 三个断点下的改动前后截图，如果能运行项目的话。
4. 一段简短的改动说明：改了什么、为什么这样改、有哪些地方刻意没动，以及还需要人来决定的事项（比如品牌主色、要不要换字体、要不要换首屏配图）。

**验收标准**
- 首屏 3 秒内能看懂“这是什么、给谁用、下一步点哪里”。
- 全页颜色不超过 3 个色相（灰阶不算），字号不超过 6 档。
- 各区块之间的间距、圆角、阴影前后一致，找不出例外。
- 原有功能、链接、表单全部正常，lint 和构建通过。

---

说明：因为没有看到你的页面，上面“高级”的方向默认是**极简、克制的品牌官网风格**（参考 Apple、Linear、Stripe 那一类）。如果你想要的是奢华感、杂志感或科技炫酷风，把“改造方向”里的色彩和动效两条换掉就行。
