**结论：未达标。** 9 项验收条件里，没有一项能确认完全达标。其中 4 项明确不达标，2 项只做到一部分，另外 3 项（键盘、触控、窄屏）交付物里完全没有涉及，无法验收。

另外，要求写的是“审查”，也就是先逐条对照验收项给出结论和证据。Agent 直接交了一版改版，没有说明每一项怎么满足，也没有截图、不同状态的画面或测试记录。这一点本身就没交齐。

## 逐项判定

| 验收项 | 判定 | 依据 |
|---|---|---|
| 找到优惠入口 | 部分达标 | 入口存在，但和发票合在一起而且默认折叠，标签看不出有几张券可用、是否已经用了券。汇总里已经显示“优惠 -¥20”，用户不知道这 20 元是哪张券、能不能换。 |
| 理解金额变化 | 不达标 | 选券后“应付金额数字直接更新，无其他提示”。没有写明用了哪张券、减了多少，也没有提醒金额变了；读屏用户完全感知不到变化。 |
| 确认支付方式 | 不达标 | 只写“已选银行卡”，没有银行名和卡号后四位，用户没法确认扣的是哪张卡。 |
| 修复字段错误 | 不达标 | 错误提示“仍在页面顶部汇总”。在手机上，顶部汇总常常已经滚出屏幕或被键盘挡住；字段旁边没有提示，点了也不会跳到出错的字段。而且主页面各项都折叠成摘要加“修改”，出错时用户找不到要改的地方。 |
| 从支付失败中恢复 | 部分达标 | 做到了：按钮禁用防止重复提交，已填内容保留。没做到：弹窗只有“请重试”，没说失败原因（余额不足、卡被拒、网络问题）；弹窗里没有“换一种支付方式”的入口；没处理“处理中”超时、结果不确定的情况（用户会担心是否已扣款，可能重复支付）；没说明失败后按钮会不会恢复可点。 |
| 键盘 | 无法验收 | 没有提到：弹窗打开时焦点去哪、关闭后焦点回到哪；输入框是否调出对应类型的键盘；软键盘弹出时是否挡住支付按钮或出错字段；出错后焦点会不会跳到对应字段。 |
| 触控 | 无法验收 | “修改”和“▸”看上去是很小的文字或图标，没有标注点击区域大小（至少 44×44pt 或 48×48dp）和相邻控件之间的间距。 |
| 窄屏 | 无法验收 | “商品 ¥268 配送 ¥0 优惠 -¥20”挤在一行，在 320px 宽的屏幕上一定会换行或挤压，没有说明怎么处理；“收货与配送”这类三栏的行在窄屏上怎么排也没说。 |
| 长文本 | 不达标（有风险） | 地址被截断成“上海…”，结账是用户最后核对地址的地方，截断会让人无法确认地址。长券名、长银行名、大金额、系统字体调大的情况都没有考虑。 |

## 必须修复（阻塞项）

1. **字段错误**：在出错字段旁边直接提示；提交失败后自动滚动并聚焦到第一个错误。如果保留顶部汇总，每一条都要能点击跳到对应字段。
2. **金额变化**：用券后，明细里写明券名和减免金额，变化的数字给出视觉提示，并让读屏软件能播报变化（aria-live）。
3. **支付方式**：显示银行名和卡号后四位，比如“招商银行储蓄卡（尾号 1234）”。
4. **支付失败**：弹窗里分原因给出文案，至少提供“重试”和“更换支付方式”两个操作；补上超时或结果未知时的处理（先查订单状态，提示“请勿重复支付”）；写明失败后按钮恢复可点。
5. **地址**：不要截断，完整显示或允许换行。

## 需要补交的材料

- 窄屏（320px）、系统大字号、长地址、长券名、大金额这几种情况下的画面。
- 字段报错、选券前后、处理中、支付失败、结果未知这几种状态下的画面。
- 键盘和焦点顺序的说明，以及可点击区域的尺寸标注。
- 一份逐条对照验收项的自查表，每条附上证据。
