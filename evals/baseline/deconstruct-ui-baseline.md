## 这段话里的专业概念

**1. 渐进披露（Progressive Disclosure）**
- **意思**：先只展示大多数人马上要用的内容，其余内容等用户主动要时再显示，比如点“更多选项”、展开或进入下一层。
- **为什么用在这里**：设置项太多，第一眼信息过载。按“低频/高频”分层后，首屏更轻。
- **代价**：被收起来的东西更难被发现，也可能要多点一步。所以评审后半句紧接着提了两个检查点。

**2. 使用频率分层（高频 / 低频）**
- **意思**：决定“放外面还是收起来”的依据是大多数用户多常用它，不是它重不重要。
- **为什么用在这里**：它决定哪些设置可以收起来。前提是你真的知道哪些是低频，最好有数据或用户反馈，不要凭感觉。

**3. 首屏信息量 / 认知负荷**
- **意思**：用户第一次看到界面时，需要理解和筛选的东西有多少。
- **为什么用在这里**：这是这次改动要解决的问题，也可以用来衡量改完有没有变好。

**4. 可发现性（Discoverability / Findability）**
- **意思**：用户需要某个功能时，能不能自己找到它。
- **为什么用在这里**：渐进披露最常见的问题就是藏得太深。“更多选项”这个入口是否显眼、名字是否说得清里面有什么，都会影响能不能找到。

**5. 交互成本 / 任务路径（Interaction Cost）**
- **意思**：完成一个任务需要多少次点击、跳转和思考。
- **为什么用在这里**：如果某个“常用”设置被误判为低频收了进去，高频用户每次都要多点一步，界面看着干净了，用起来反而更慢。

**整体逻辑**：用渐进披露降低认知负荷，同时守住可发现性和常用路径的交互成本这两条底线。

## 以后什么时候主动用这些词

| 你遇到的情况 | 用这个词 |
|---|---|
| 页面、表单或设置“太乱”“太多” | 渐进披露、首屏信息量 |
| 要决定哪些功能放外面、哪些收起来 | 使用频率分层 |
| 担心用户“找不到” | 可发现性 |
| 担心改版后“变麻烦了” | 交互成本、常用任务路径 |
| 新手和老手的需求冲突 | 渐进披露（默认给新手简洁版，给老手留高级入口） |

## 怎么对 Agent 说

**让它设计时：**
> 这个设置页信息太多。请用渐进披露重新组织：按使用频率把设置分成高频和低频，高频的直接展示，低频的收进“更多选项”。列出你的分组和判断依据。

**让它自查或评审时：**
> 检查这个方案的两个风险：① 可发现性，被收起的设置用户能不能找到，入口的名字是否说清楚了里面有什么；② 交互成本，列出最常用的 3 个任务，对比改动前后各需要几步。

**关键**：说“渐进披露”的同时，要把验收标准（找得到、常用任务不变慢）一起说清楚，否则 Agent 可能只顾着“收起来”。
