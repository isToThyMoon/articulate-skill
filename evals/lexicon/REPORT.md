# 领域知识库流程测试

目标：从形容词驱动走向领域模型驱动，而非只保存术语释义。实现位于 shared/lexicon.md，按需分发到三个 skill。

复用两个 GPT-5.6 Sol 会话，在隔离临时目录执行；不是全新盲测或真实用户学习实验。主 agent 检查文件与实际回复。

## 实际用例

1. **建立并调用**：用户提供视觉层级与信息分组两段教学知识，要求离线保存到指定目录；随后要求用库把“页面专业一点”转为 Agent 要求，无截图、不追问、不改库。见 [完整回复](responses.md) 与 [库快照](library/index.md)。生成条目包含定义、关系、工作位置、评价、调用示例及未联网边界；调用结果不预设问题存在，按主次/分组区分检查与验收。执行者报告第二步未改库，未采集该步前后独立文件快照，故只读结论不声称已独立取证。
2. **位置未定**：用户通过 unpack 要求存入词库但没给位置。见 [原始回复](location-response.md)。执行者先询问位置并给候选内容，没有创建用户库；测试输出路径未作为库路径。回复暴露了测试路径，是表达噪音，不作为理想交互示范。
3. **增量更新**：先在测试库植入人工备注；用户要求补充别名并加入未验证的新说法“按钮最大就一定是主操作”。见 [更新回复](update-response.md)。实际保持两个条目，人工备注保留，索引增加别名，新说法单列待核查而未替换原定义；信息分组条目的 SHA-256 更新前后均为 a68990e1995b7a98c51a5975d3fd21579649e298a61cfef4d0f6fd77d33d0ca4。

## 边界与结论

样本展示了保存、问题检索、条件化表达、位置确认、去重补充和冲突保留，未生成学习进度。快照只覆盖相关类别，不伪造八类都有内容。来源粒度仍可改善：模型补充的通用解释没有逐段单独标记，但明确整体未外部核查；不能将本测试库当已审核的专业资料。

未测大型知识库、多义术语、并发更新、外部存储服务或长期检索收益。此次完成的是可选知识库工作流，不是自动知识管理后台，也不证明用户能力提升。

机械检查：三个 skill 格式、内部引用、共享副本一致性、同步脚本语法及本机安装内容一致性通过。
