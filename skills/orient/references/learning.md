# 学习与检验

## 核心概念与理解顺序

用户接受地图后的邀请，或要求挑核心词、安排学习顺序时，从现有地图筛选。数量和分支遵从请求；未指定时选择足以串起关键关系的一组。

优先选择支撑后续理解、帮助表达要求或避免重要误判的概念。每项给名称与简明含义、优先理由、先决概念，以及一项 Agent 要求或检查问题。

按理解依赖组织，解释关键依赖的理由。互相依赖的概念成组对照，独立分支并列；教学建议顺序与真正先决条件分别说明。

紧凑请求用每个概念组一行的表格或列表，每格一句，合并含义、依赖理由和一条应用表达；篇幅优先给关键区别。

完成条件：每个概念组写明先决项、依赖理由和一条 Agent 要求或检查问题，并推荐一个起点；已要求开始讲解时直接展开。

## 深入概念

从选定分支进入，或推荐能串起关键关系的代表案例。先呈现问题，再解释机制、边界和易混淆项，最后展示改变一个条件后怎样应用。

以“现象 → 候选解释 → 区分证据 → 选择 → 验收”组织有用的对照。基础知识按理解缺口补充。

完成条件：解释连接到一项更准确的要求、一个值得补问的条件，或一种不合格结果。

## 用户请求检验时

一次提出一道新情境题并等待回答；要求批量自测时给一组题并把参考答案分开。通过改变关键条件检验解释、区分、表达、判断或迁移。

反馈锚定用户的具体回答：哪些判断成立，缺口影响什么。需要时用更小的对照示例重讲，持续困难时缩小目标或给带解释的示范。

完成条件：反馈引用了用户回答中的具体判断，并给出一个修正方向。

## 时间预算

按用户预算缩短条目与案例深度，保留全景结构和应用过程。一小时可安排定边界、看地图、沿案例理解、形成要求和可选练习，时间随实际交流调整；目标表述为获得初步导航并在一个情境中试用。
