# 地图交付

首轮交付：领域总览 → 八类地图 → 贯穿案例 → 导航。按用户所需深度控制篇幅，让全景和实际应用同轮可见。用户列出了具体交付物时，按所列交付，贯穿案例改为导航中的一句邀请。

用户要求紧凑时，地图用八行表格，每格最多两句、三个左右代表条目；案例压成一段叙述；导航用几行列表，含提问要素。连同学习顺序一并请求时，为后半部分留出篇幅，细节留在用户选择深入后展开。

## 总览与八类地图

先说明领域解决什么问题、主要子域及本次边界，再用简明关系描述或小图展示骨架。

按共同方法的八类覆盖主要分支。每个核心条目说明名称、解决的问题及一条有意义的关系；重要关系解释理由和条件。用“依赖、约束、测量、可能导致、替代”等动词区分关系。术语区作为检索索引，每个词附一句含义，或指明解释它的条目。

选择能支持关键决策的内容，合并同义项，跨类内容只完整解释一次。缺少正式标准的领域说明这一事实，列出确实存在的指南或方法。

完成条件：八类各有实质内容或不适用理由；主要子域可见或列入未展开范围；核心条目的关系写明理由。

## 贯穿案例

选择具体对象和有限目标。真实材料之外的情境标为教学假设，模拟观察与验收结果同样标明。

案例从一个模糊意图出发，交代观察到的条件，说明依据哪些概念做出选择，展示一个可读的成果片段（如结构草图、诊断项或方案段落），再给出一次评价，以及失败时回到哪一步。

案例中的确定选择依据观察或明确假设；缺证据的部分形成检查要求。让用户看见约束的来历。

评价写出观察结果，以及据此保留或修订的决定；没有真实结果时用标明的教学模拟。

完成条件：案例既有决策，也有实际产物片段及一次真实或明确模拟的评价，读者可追溯“为什么这样做”。

## 导航

给出推荐起点及理由，区分先决概念与兴趣分支。

给一份**提问要素**：向 Agent 提问时应交代的条件（来自约束最强的实体与概念），以及判断回答是否可靠的信号（来自评价与失败模式）。

关键主张附近附依据，导航中简述真实产物、失败案例等资料补充或收窄了什么，哪些证据尚缺。

用户已经要求学习顺序时读取 [learning.md](learning.md) 并同轮交付。否则可简短邀请：“要继续从这张地图挑出最值得先理解的核心概念，按理解依赖排列吗？也可以选一个分支深入。”

完成条件：本轮范围、关键依据、证据缺口、推荐起点和提问要素均已写明。
