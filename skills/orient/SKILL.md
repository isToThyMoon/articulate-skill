# Orient

帮助用户知道一个领域的重要问题、它们怎样关联，以及如何用这些知识向 Agent 提出准确要求。

开始时读取 [共同方法](references/foundation.md)。八类建立全景，五层把知识连接到表达与判断。

## 选择路径

根据当前请求和已有上下文进入对应路径：

| 用户需要 | 读取并执行 | 完成标志 |
|---|---|---|
| 进入新领域、建立地图 | 下述地图流程 | 有边界的全景、应用示范和下一步入口 |
| 挑核心词、安排顺序、深入概念、检验理解 | [学习与检验](references/learning.md) | 概念路径、解释或一次情境反馈 |
| 保存、检索或更新领域知识 | [知识库](references/lexicon.md) | 可检索条目或适用于当前问题的表达 |

复用已有地图和材料。用户接受上轮“挑核心概念”的邀请时，直接交付学习顺序。具体诉求澄清与产出验收属于 clarify，拆解专业材料属于 deconstruct；这类请求出现在本 skill 中时，直接完成当前任务。

## 地图流程

### 1. 定边界

从用户信息确定领域、视角和深度。背景较少时采用入门解释，说明暂定范围。领域过宽时先展示主要分支；只有选择会显著改变答案时，问一个关键问题。

有项目就用作例子，一般入门则选择代表性教学情境。完成时，边界已写明：本次涵盖的分支，以及暂不展开的相邻领域。

### 2. 获取知识

读取 [来源与交叉检查](references/sources.md)，执行候选结构 → 互补资料 → 主张核查 → 修订地图。内化知识提供结构与关联，外部材料补充、核实和挑战它。

完成时，主要分支与关键判断有适当依据，真实产物和失败案例有内容落点或清楚的获取缺口。

### 3. 交付地图

读取 [地图交付](references/map.md)，给出总览、八类地图、贯穿案例和导航，深度随请求调整。

完成时，核心条目各带一条有理由的关系；给出的案例走完从模糊意图到评价与返工的全程；导航给出向 Agent 提问的要素与判断回答可靠的信号。

### 4. 衔接下一步

已要求学习顺序或应用时，同轮继续完成。否则用一句邀请提供最有用的下一步：筛选核心概念并按理解依赖排列，或深入选定分支。用户决定走哪条路。
