# Explain

讲清一个领域词：它叫什么、解决什么问题、怎样工作；需要时再讲何时该想到它、怎样判断用对了，以及怎样用它向 Agent 提出要求。

开始时读取 [共同方法](references/foundation.md)。

## 1. 定位

解释 $ARGUMENTS；未提供时取用户当前问的词。词来自用户给的材料时，先讲它在原文中的用法，再讲一般含义。用户陈述了自己的理解时，记下要逐条判定的点。

选择路径：用户只问是什么、怎么工作，走**短路径**；用户问何时用、怎么用、怎么对 Agent 说，或要求完整解释，走**完整路径**。

完成条件：确定了要解释的词、所走路径，以及要判定的用户理解（如有）。

## 2. 核实与演示

概念较新或快速演化（近两年出现，或大版本迭代频繁）时，联网核实官方文档与主流实现，引用紧贴其支持的主张；成熟稳定的概念说明依据即可。

用适合该领域的方式演示。示例代码先实际运行再给出，附运行结果，优先零依赖、可直接复制运行；依赖外部服务跑不了的，标注“未运行”。非代码概念用反例、对照样本或推演。

完成条件：关键主张有依据；给出的代码都已运行或标明未运行。

## 3. 按五层讲清

| 层 | 讲什么 |
|---|---|
| 词汇 | 一句话定义，用用户已知的概念类比（“X 之于 A ≈ Y 之于 B”）；别名与易混词 |
| 概念 | 解决什么问题、机制如何；反事实：没有它会怎样 |
| 关系 | 时间线：之前的做法卡在哪；替代或后继方案及各自适用条件；它依赖或约束哪些概念 |
| 工作流 | 在任务的哪一步用到它，什么信号出现时该主动想到它 |
| 评价 | 怎样判断用对了；常见误区和不适用场景 |

短路径讲透词汇与概念，演示只保留最能说明机制的一个；关系、工作流、评价合计不超过三句。完整路径五层都展开，最后给一条可移交的 Agent 提问或要求，写明这个词及其适用条件。

用户陈述了自己的理解时，逐条判定对、部分对或错，指出错在机制、层次还是术语。

呈现顺序、详略和体裁按概念本身选择：有的反例先行，有的代码先行，有的一条时间线就够。不适用的项跳过，成熟概念没有替代方案就不写。

完成条件：短路径写明定义、机制和至少一个误区或不适用场景，其余三层合计不超过三句；完整路径五层各有内容或写明不适用，并附一条可移交表达。

## 输出去向

用户提供 Notion 页面链接时，完整版写入该页面，聊天里给核心结论和关键示例；后续追问的澄清同步回文档。用户明确要求保存或检索知识时，读取 [知识库](references/lexicon.md)。
